## Подарить VPN

В главном меню доступны «🎁 Подарить VPN» и «Мои подарки».

1. Даритель выбирает одного человека через список пользователей Telegram. Получателю не нужно заранее запускать бота.
2. Затем выбирает тариф, срок и способ оплаты. Перед оплатой видны имя и Telegram ID получателя, стоимость и условия подарка.
3. После подтверждения оплаты бот создаёт отдельную VPN-подписку на аккаунте получателя. Срок начинается после оплаты; действующая платная подписка получателя сохраняется.
4. Даритель получает карточку с кнопками «Открыть подписку» и «Отправить подарок». Ссылку можно снова открыть в «Мои подарки» → «Отправленные» или командой `/gifts`.
5. Получатель видит подарок в «Мои подарки» → «Полученные». Если он ещё не запускал бота, даритель отправляет приглашение. При первом входе получатель проходит обычное принятие правил и открывает уже оплаченную подписку.

Ссылка подключения доступна обоим участникам. Ссылка-приглашение открывает карточку только для дарителя и выбранного получателя. Пересылка приглашения третьему человеку не передаёт ему подарок. Для выбора используется неизменный Telegram ID; изменение username не меняет владельца.

Для подарков доступны публичные платные тарифы `ALL` с базовым числом устройств. Персональные и разовые скидки не расходуются; реферальные награды за подарки не начисляются. Подарок не продлевает основную подписку: у него собственные срок и ссылка. Если основной подписки нет, она истекла или была пробной, подарок становится основной подпиской. При действующей платной подписке подарок открывается из «Полученных».

Статусы карточки: ожидает оплаты, оплачен и готовится, подписка готова, получатель открыл подарок, срок закончился, оплата отменена или возвращена. Ошибка доставки сообщения не отменяет покупку. Повторный callback оплаты не увеличивает срок и не создаёт второй доступ. Worker раз в минуту повторяет незавершённую выдачу и доставку уведомлений. При подтверждённом возврате отключается только подписка этого подарка.

Для запуска примените миграции `0042_add_broadcast_message_ids` и `0043_add_gifts`, затем обновите бота и worker. Миграция `0042` поддерживает рассылки альбомов. Релиз сохраняет действующие серверные исправления рассылок и HWID-группы при продлении. Новые переменные production-конфигурации не требуются.

Проверки находятся в `tests/test_gifts.py`. Интеграционные проверки используют отдельный PostgreSQL через `GIFT_TEST_DATABASE_URL`; Telegram, платёжный провайдер и Remnawave в них подменены. Без этой переменной проверки БД пропускаются. Реальную оплату и клиентский интерфейс Telegram нужно проверить после развёртывания.
