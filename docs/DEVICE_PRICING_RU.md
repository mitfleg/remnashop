# Выбор количества устройств

Функция работает только для тарифов с лимитом устройств. Старые тарифы после миграции
остаются фиксированными и не меняют цены или лимиты.

## Настройка тарифа в Telegram

1. В поле «Устройства» укажите фиксированное значение `4` или диапазон `4-10`.
2. Для каждой длительности и валюты укажите цену в формате `700 + 100`:
   - `700` — базовая цена, включающая 4 устройства;
   - `100` — доплата за каждое устройство сверх четырёх.
3. Сохраните тариф.

Клиент увидит выбор количества устройств перед выбором длительности. Итоговая цена
рассчитывается на сервере:

`базовая цена + доплата × (выбранный лимит − базовый лимит)`

Промокод применяется после добавления стоимости устройств. Выбранный лимит сохраняется
в снимке транзакции и передаётся в Remnawave при покупке, смене и продлении.

## Совместимость

- Фиксированный тариф: `4` и обычная цена `700`.
- Настраиваемый тариф: `4-10` и цена `700 + 100`.
- Для XTR и USD доплата может быть дробной; округляется только итоговая сумма.
- Продление сохраняет ранее оплаченное количество устройств, если оно остаётся в диапазоне.

## Remnawave v3

Совместимость v3 встроена в исходный код. Старые UUID сопоставляются с числовыми ID через
файл `REMNAWAVE_V3_USER_MAP`, по умолчанию:
`/opt/remnashop/assets/remnawave-v3-user-map.json`.

Исключения из HWID-лимита задаются переменной
`REMNAWAVE_HWID_LIMIT_EXEMPT_USER_IDS` как список числовых ID через запятую.

## Собственный Docker-образ

После push в `main` workflow `Remnashop - Custom Image` публикует два тега:

- `ghcr.io/mitfleg/remnashop:custom`;
- `ghcr.io/mitfleg/remnashop:custom-<sha>`.

На сервере официальный Compose подключается вместе с
`deploy/docker-compose.custom-image.yml`. Для контролируемого деплоя следует использовать
неизменяемый digest либо тег `custom-<sha>`, а не плавающий тег `custom`.
